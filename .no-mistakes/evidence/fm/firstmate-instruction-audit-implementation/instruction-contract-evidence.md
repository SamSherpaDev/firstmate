# Instruction-contract evidence

The product surface is the generated worker instruction, not a rendered UI.
These are actual CLI-generated outputs from isolated fixtures, not implementation-source snapshots or model responses.
Fixture paths in the files identify disposable synthetic homes; they are not production task data.

## Launch-boundary reproduction

The baseline generator emitted [the pre-update no-mistakes brief](pre-update-no-mistakes-brief.md), including premature completion and a second validation-start instruction.
The current spawn CLI consumed that stored brief without modifying it.
Its emitted launch command was executed against a capturing codex executable over a fake tmux transport, with a real isolated Git worktree.
The received operational envelope decoded byte-for-byte to the published launch brief.
For every delivery mode, its effective DOD matched a fresh brief generated by the current CLI.
No real agent, validation pipeline, remote forge, or live backend was invoked.

## Reproduction and limits

Run `/bin/bash capture-instruction-contract.sh` from the validated worktree using [the capture script](capture-instruction-contract.sh).
The script uses repository fixture helpers and stock macOS Bash 3.2.
The targeted automated run exercised brief generation, delivery and promotion, worker authority instructions, isolated Herdr lab tripwires with a stateful fake client, and exact-key decision resolution through real CLI consumers over stubbed transports.
Integration inspection confirmed the common launch brief feeds positional-prompt adapters and the Kimi/Rovo pointer adapters before backend-specific delivery.
This proves instruction emission and transport, not an LLM's obedience or the third-party publisher's output.
No new vendor-signal or live-harness capability claim is made.
Lint, document validation, PR publication, and CI remain with their assigned outer phases.
